= Starting an automated migration report with a VMware agent

[role="_abstract"]
The assisted migration agent connects to the Migration Planner service, collects vSphere data according to your configured policies, and sends data to the {HCC} in supported modes. The following steps provide a typical, high-level sequence. For the authoritative steps, follow the instructions you receive when you generate or download the OVA, and see the agent and planner documentation for your version.

[NOTE]
====
For a hands-on Arcade demo of deploying and using the OVA agent with the {OMA}, see link:https://interact.redhat.com/share/kEinYphM8Zyt7wXLys53[The OpenShift migration advisor using OVA Agent].
====

.Prerequisites

* A VMware vSphere deployment where you can import an OVA and power on a VM that meets the image requirements.
* Network and firewall settings that enable the agent to connect to the reporting and planner endpoints in the mode that you select (*connected* or *disconnected*), and any proxy settings that your site requires. Your organization must allow these connections under its policies.
* Identifiers that the service assigns, such as an *agent* ID and *source* ID in UUID format, and a folder of OPA policy files if your environment requires OPA for VM validation. Use the value placeholders that your operator provides, not examples from a document.
* Optional JWT or other authentication material if the console in your environment requires a token to register the agent with the planner service. This material must be generated through the process that your organization uses, not with sample keys from a repository.

.Procedure

. In the {HCC}, start a new automated migration report and choose the agent-based path if it is available. Alternatively, click *Generate* or *Download agent* if either option is displayed before an automated report is created, depending on your environment.
. Record the UUIDs and any registration steps that are provided. Store secrets in a password safe, not in plain text in tickets or wikis.
. Import the OVA into the VMware cluster that your design specifies. Allocate CPU, memory, and disk to match the *release notes* for the *agent image* that you are using, not a generic size.
. Configure the agent to run in the mode that your design requires, *connected* or *disconnected*, and point it to the *console* and *planner* endpoints that are specified in the product user interface or by your {RH} operator for your environment only. Do not copy internal hostnames from a lab into production.
. Start the agent and confirm in the {HCC} that the *source* moves to a healthy, reporting state by using the status that is displayed.
. After the automated report is complete, open the results in the {HCC}. If your environment also provides a local appliance with a report view, use that for any detailed views that are documented for that path.

.Next steps

* Review the automated report outputs as described in _Interpreting risks and migration considerations in an automated migration report_. For command lines, flags, and version-specific deployment details, see the {RH} *Migration Planner* and assisted migration *agent* documentation for your product version, not generic upstream examples.

[IMPORTANT]
====
Example commands in open-source repositories are technical references only. Use your own tokens, UUIDs, and endpoints. Never post credentials or real identifiers in a public or shared log.
====
