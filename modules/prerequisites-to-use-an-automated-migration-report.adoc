= Prerequisites to use an automated migration report

[role="_abstract"]
You need the following in place before you can complete a useful automated report. Exact checks appear in the console in your build.

* A {RH} account with access to the {OMA} in the {HCC}. Your organization must have an entitlement through a {RH} subscription or another eligible program.
* A supported web browser to load the Red Hat Hybrid Cloud Console. For details about web browser requirements, see the Browser Support link at the bottom of the link:https://console.redhat.com/[Hybrid Cloud Console] landing page.
* *For RVTools* — The ability to run RVTools in your vSphere environment and to export an RVTools spreadsheet in a supported format for upload.
* *For an agent* — A VMware vSphere deployment where you can import the assisted migration agent OVA and power on a VM that meets the image requirements for your release, as described in xref:modules/starting-an-automated-migration-report-with-a-vmware-agent.adoc#starting-an-automated-migration-report-with-a-vmware-agent[Starting an automated migration report with a VMware agent], network paths that allow the agent to reach the reporting service when you use connected mode, and credentials or tokens as the product user interface and your security policy requirements
* Familiarity with your own change control and with who may approve data leaving your data center, even in anonymized form, if a collection path or optional data sharing is offered
* *OpenShift* — You do not have to be an {OSV} day-one expert to *start* an automated report. You need a basic understanding of why you are targeting {OSV} and who will own the target design after the automated report
